# ModernMac

Menu bar app for macOS 14–15 (Swift, SwiftUI + AppKit) that replaces the stock volume and brightness overlay with a modern HUD in three styles: `tahoe` (macOS 26 look), `notch`, `circular`. It intercepts the media keys with an event tap, applies the change itself, and draws its own HUD.

`docs/SPEC.md` is the source of truth for scope, architecture, numbers and phases. Read the sections relevant to the task before writing code. `docs/FINDINGS.md` records what was actually observed on this Mac; it overrides assumptions in the spec.

## Commands

Always go through the Makefile.

- `make build` — regenerate the Xcode project and build Debug
- `make test` — unit tests
- `make run` — build, replace any running copy, launch
- `make kill` — stop the running app
- `make logs` — stream the app's log (subsystem `com.ando.ModernMac`)
- `make simulate ARGS="kind=volume&level=0.6&style=tahoe"` — show the HUD without touching hardware
- `make snapshots` — render every style to PNGs in `.build/snapshots/`

`ModernMac.xcodeproj` is generated by XcodeGen from `project.yml` and is git-ignored. Change `project.yml`, never the project file.

## How to verify your own work

1. `make build` and `make test` must pass before you call anything done.
2. For anything visual, run `make snapshots` and look at the PNGs yourself (Read tool) before asking Ando to look. Compare with `docs/reference/` when screenshots are there.
3. For behaviour, use `make simulate` and `make logs`.
4. You cannot press physical keys, grant permissions, or see live blur and animation. When a step needs that, stop and give Ando a short numbered checklist of exactly what to do and what he should see. Do not report those things as working until he confirms.

## Rules that matter here

- **Fail open.** If ModernMac cannot handle a key (no permission, no controllable device, an API error, feature toggled off), pass the event through untouched so macOS handles it. The user must never lose their volume or brightness keys.
- **The event tap callback stays trivial.** Decode, decide, one fast hardware call, return. No logging at info level, no allocation-heavy work, no waiting. Slow taps get disabled by the system and can stall all keyboard input.
- **Private API stays in one file.** `Sources/Display/DisplayServicesBridge.swift` loads DisplayServices with `dlopen`/`dlsym`; every symbol is optional. Do not link private frameworks and do not add other private APIs without asking.
- **Core is pure.** `Sources/Core` and `HUDCoordinator` import only Foundation. Hardware sits behind `VolumeControlling` / `BrightnessControlling`; tests use fakes.
- **The HUD never takes focus.** Non-activating panel, never key or main.
- **No sandbox**, hardened runtime on. Minimum deployment target macOS 14.0; do not use APIs that need the macOS 26 SDK.
- **Write code fresh.** SlimHUD, MewNotch and similar projects are GPL-3.0: do not copy code from them.
- **No third-party dependencies** unless Ando agrees first.
- Debug hooks (simulate URL, snapshot mode) are wrapped in `#if DEBUG`.

## Conventions

- Swift language mode 5, `@MainActor` on UI and coordinator types, `@Observable` for models, `os.Logger` for logging (debug level for per-event detail).
- Style numbers (sizes, radii, springs) live as named constants at the top of each style file so they can be tuned in one place.
- One phase per session, following `docs/SPEC.md` §8. At the end of a phase: tests green, commit, update `docs/FINDINGS.md` and the spec if reality differed, then stop for Ando's manual check.
- If the spec is wrong or ambiguous, say so and propose the change instead of quietly working around it.

## Signing note

The Accessibility grant is tied to the code signature. Debug builds are signed with the identity in `Config/Local.xcconfig` (git-ignored) so the grant survives rebuilds. If the grant gets stuck: `tccutil reset Accessibility com.ando.ModernMac`, then relaunch.
